# 单机架构规划

本文是后续设计，不表示对应系统已实现。当前代码基线仅为官方 Third Person C++ 模板，含用户批准保留的变体。

| 领域 | 规划职责与边界 |
| --- | --- |
| 核心框架 | GameMode 管理当前游戏规则；GameInstance Subsystem 管理跨地图本地会话；LocalPlayer Subsystem 管理本地玩家服务。按阶段引入，避免全局单例与循环依赖。 |
| 角色控制 | PlayerController 处理本地输入与 UI 焦点；Character/MovementComponent 负责移动、跳跃、相机；Enhanced Input 管理映射。 |
| 战斗 | 独立组件管理动作状态、命中和伤害规则；动画只发送明确事件；本阶段不实现。 |
| 属性与技能 | 数据资产定义配置，运行时组件保存可变状态；是否使用 GAS 留待需求和成本评估，不提前引入。 |
| 怪物 AI | 后续评估 AIController、感知与 StateTree；不让关卡蓝图承载核心 AI。官方模板变体不是本项目 AI 交付。 |
| 地图与场景 | 地图按区域组织；先验证小型关卡，再根据预算决定 World Partition/流送；所有 `.umap` 使用 LFS。 |
| 背包和装备 | 稳定物品 ID、只读定义和运行时实例分离；装备效果通过明确接口应用到角色，不直接耦合 UI。 |
| 任务 | 数据驱动定义、可序列化本地任务状态、明确事件接口；不以场景 Actor 指针作为持久存档键。 |
| 本地 SaveGame | 带版本号、稳定 ID、校验与迁移策略；采用本地槽位和可恢复写入；不使用在线数据库。 |
| UMG UI | UI 展示状态并发出意图，核心规则留在 C++；避免逐帧轮询和跨 Widget 强依赖。 |

依赖方向：资源定义 → 运行时领域组件 → 玩家/游戏框架 → UI 与表现。保存层序列化领域状态，而非整个 UObject 图。日志与测试通过稳定接口观测状态。

本项目只提供离线单玩家体验；不引入 RPC、复制、服务器、EOS 或网络账户。后续模块拆分必须有真实调用边界和构建证据，不预建空模块。
